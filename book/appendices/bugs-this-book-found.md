# Bugs this book found

Writing this book meant building small fonts that exercise one thing each, shaping text with them, and checking every result against the code and the specifications ([Testing with a font of your own](testing-harfbuzz.html#testing-with-a-font-of-your-own)). Some results didn’t match. Those are drafted as bug reports in [`notes/upstream-bug-reports.md`](https://github.com/Lorp/how-harfbuzz-works/blob/main/notes/upstream-bug-reports.md), in the book’s repository, 86 so far, the first 83 reproduced on HarfBuzz 15.1.0 (commit `3df40d9b`), the version the book then described, and the last three on 15.2.0, most with a font or a command that needs nothing from this book. This appendix lists them all. What they suggest about where bugs are left to find is in [Where the bugs are](testing-harfbuzz.html#where-the-bugs-are).

**Two are on HarfBuzz’s issue tracker.** HHW-71 is issue [#6827](https://github.com/harfbuzz/harfbuzz/issues/6827), now closed, and HHW-82 is [#6828](https://github.com/harfbuzz/harfbuzz/issues/6828), still open. The rest went to HarfBuzz’s author directly, and most are fixed, in HarfBuzz 15.2.0 or since (see the last column below), but they are still drafts, written by the book’s authors. Some are certainly bugs, some are matters of policy that HarfBuzz’s developers may well decide the other way, and a few were found by reading code and have no example yet. One, HHW-7, turned out not to be a bug, and is withdrawn.

Each draft keeps its number for good, and its ID, such as HHW-75, is how HarfBuzz’s pull requests cite it (“How HarfBuzz Works bug 75”). A withdrawn draft keeps its number too.

The tables below give each draft’s number in that file, a one-line summary, the chapter that describes the behavior, and how it was checked:

* **Live.** The chapter showed the behavior in a live block, built from HarfBuzz 15.1.0. Where 15.2.0 fixed it, the block now shows the fix.
* **Run.** Reproduced with HarfBuzz’s tools or a small program, but not shown live.
* **Read.** Found by reading the code.

The last column records what has happened upstream. Drafts 1–65 were shown to HarfBuzz’s author, Behdad Esfahbod, on 17 November 2026, and he fixed many of them on the `main` branch the same day; most of the rest were fixed over the next three days. HarfBuzz 15.2.0, released on 20 November 2026, has every fix merged up to 19 November. Every draft was checked again against `main` at commit `8846dbbf6` (20 November), by rerunning its example or, for those found by reading, reading the code again. On 21 November the drafts not yet fixed, and those about the renderers, were checked once more, against `main` at `1b988bc38`. The column says “fixed in 15.2.0” or “fixed on main”, for a fix merged after the release, with the pull requests that fixed the draft (`notes/upstream-bug-reports.md` has the commits); “partly fixed” where some of a draft’s items are fixed; “changed” where the behavior is different but the problem remains; “declined” where HarfBuzz’s developers decided to keep the behavior; “open” where the draft still describes `main`; and “withdrawn” where the draft turned out to be wrong. Related issues come from a keyword search of HarfBuzz’s issues and pull requests, which isn’t exhaustive.
